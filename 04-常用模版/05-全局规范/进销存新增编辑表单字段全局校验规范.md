# 进销存新增编辑表单字段全局校验规范

> **文档定位**：强盛进销存项目的全局通用产品规范。用于统一主数据、业务单据新增/编辑页的字段输入、校验时机、错误反馈和验收口径。
>
> **适用对象**：产品经理、AI 协作者、前端研发、后端研发、测试人员。
>
> **适用范围**：客户、供应商、商品、仓库等主数据，以及销售订单、采购订单、入库单、出库单、收付款单等业务单据。
>
> **不包含**：具体框架代码、数据库字段类型、接口协议和某一模块的特殊业务规则。
>
> **版本**：V1.0 | 更新时间：2026-06-14

---

## 一、核心原则

1. 本规范定义全系统共用的默认校验模板和前端交互纪律。
2. 模块字段清单是模块字段定义的唯一权威源（Single Source of Truth）。
3. 主 PRD 定义跨字段、跨行、状态、动作及保存/提交等业务校验。
4. Demo PRD 将字段清单和主 PRD 转写为可生成、可交互、可验收的页面行为。
5. 模块存在特殊规则时必须显式声明覆盖，不得静默偏离本规范。
6. 前端校验用于及时反馈，服务端必须对保存、提交、唯一性和业务规则再次校验；服务端结果为最终口径。

### 1.1 规范优先级

发生冲突时，按以下顺序执行：

```text
模块主 PRD / 模块字段清单中的显式特殊规则
    > 本全局规范的默认模板
    > Demo PRD 中的页面转写
    > 前端自行推断
```

Demo PRD 与字段清单或主 PRD 冲突时，应回到权威源修正，再重新生成 Demo PRD，不允许用 Demo PRD 反向覆盖业务规则。

### 1.2 文档分工

| 层级 | 负责定义 | 不负责定义 |
| :--- | :--- | :--- |
| 本全局规范 | 通用字段模板、默认字符/长度/精度、校验时机、错误展示纪律 | 某张单据的条件必填、状态流转和特殊边界 |
| 模块字段清单 | 字段类型、必填性、模板绑定、默认值、范围、模块覆盖、是否可编辑 | 页面布局、错误出现位置、失焦或点击时的视觉行为 |
| 模块主 PRD | 保存/提交条件、跨字段/跨行规则、状态动作、服务端阻断规则 | 控件尺寸、红框、滚动定位等页面表现 |
| Demo PRD | 控件、输入限制、校验触发、错误展示、Mock 与页面验收项 | 重新定义字段含义、枚举、公式和业务规则 |
| 前端工程 | 输入清洗、校验函数、错误态 UI、服务端错误映射 | 自行补充产品未定义的规则 |

## 二、全局字段校验模板

### 2.1 文本与编码类

| 模板编码 | 适用场景 | 默认规则 | 默认错误文案 |
| :--- | :--- | :--- | :--- |
| `CODE_50` | 外部编码、业务编码 | 1～50 个字符；允许字母、数字及 `._/-`；自动 trim | 请填写{字段名称} / {字段名称}仅支持字母、数字及 `._/-` / {字段名称}不能超过 50 个字符 |
| `NAME_100` | 客户、供应商、商品、仓库等名称 | 最长 100 个字符；自动 trim；必填时 trim 后不得为空 | 请填写{字段名称} / {字段名称}不能超过 100 个字符 |
| `SHORT_TEXT_100` | 原因、简称、简短说明 | 最长 100 个字符；自动 trim；允许中英文、数字及常用标点 | {字段名称}不能超过 100 个字符 |
| `REMARK_200` | 单据备注 | 最长 200 个字符；允许换行；自动 trim | {字段名称}不能超过 200 个字符 |
| `REMARK_500` | 跟单记录、详细说明 | 最长 500 个字符；允许换行；自动 trim | {字段名称}不能超过 500 个字符 |
| `ADDRESS_200` | 地址行 | 最长 200 个字符；自动 trim | {字段名称}不能超过 200 个字符 |
| `EMAIL_100` | 邮箱 | 最长 100 个字符；非空时校验邮箱格式；自动 trim | 请输入正确的{字段名称} |
| `PHONE_20` | 手机号、联系电话 | 最长 20 个字符；允许数字、空格、`+`、`-`；自动 trim | 请输入正确的{字段名称} |
| `TAX_ID_30` | 税号、统一社会信用代码 | 最长 30 个字符；默认允许大写字母和数字；是否唯一由模块声明 | 请输入正确的{字段名称} / {字段名称}不能超过 30 个字符 |

> 模块可以覆盖字符、长度和格式规则。例如某类外部税号无法统一校验格式时，应在模块字段清单中明确写明“覆盖 `TAX_ID_30`：仅校验长度与唯一性”。

### 2.2 数量、金额与比例类

| 模板编码 | 适用场景 | 默认规则 | 默认错误文案 |
| :--- | :--- | :--- | :--- |
| `INTEGER_POSITIVE` | 订货数量、采购数量、入库数量 | 正整数；最小值 1；最大值由模块字段清单声明 | 请输入大于 0 的整数 / {字段名称}不能超过{最大值} |
| `INTEGER_NON_NEGATIVE` | 累计数量、缺量数量 | 非负整数；最小值 0；通常为系统计算或回写 | {字段名称}不能小于 0 |
| `DECIMAL_QUANTITY` | 重量、体积等允许小数的数量 | 非负数；默认最多 4 位小数；最大值由模块声明 | {字段名称}必须大于等于 0，且最多保留 4 位小数 |
| `AMOUNT_2_POSITIVE` | 单价、付款金额 | 大于 0；最多 2 位小数；最大值由模块声明 | {字段名称}必须大于 0，且最多保留 2 位小数 |
| `AMOUNT_2_NON_NEGATIVE` | 折扣金额、税额、汇总金额 | 大于等于 0；最多 2 位小数；最大值由模块声明 | {字段名称}不能小于 0，且最多保留 2 位小数 |
| `PERCENT_2` | 税率、折扣率 | 0～100；最多 2 位小数 | {字段名称}应在 0～100 之间，且最多保留 2 位小数 |

数值类字段必须在模块字段清单中确认最大值。若业务尚未确认，标记为“待确认”，不得由 AI 或前端自行假定生产上限。

### 2.3 日期与引用类

| 模板编码 | 适用场景 | 默认规则 | 默认错误文案 |
| :--- | :--- | :--- | :--- |
| `DATE` | 订单日期、业务日期 | 合法日期；展示格式 `YYYY-MM-DD` | 请选择{字段名称} |
| `DATETIME` | 创建时间、审核时间 | 合法日期时间；展示格式 `YYYY-MM-DD HH:mm:ss`；通常系统生成 | {字段名称}格式不正确 |
| `REFERENCE_ACTIVE` | 客户、供应商、商品、仓库、业务员 | 必须引用存在且可用的主数据；禁用数据不可新选 | 请选择{字段名称} / 所选{字段名称}已禁用，请重新选择 |
| `ENUM` | 状态、类型等固定选项 | 取值必须来自字段清单定义的枚举 | 请选择正确的{字段名称} |

引用字段应存储稳定 ID，并按字段清单要求展示编码、名称或快照。用户输入的搜索关键词不是最终字段值。

### 2.4 空值与字符计数

| 项目 | 全局口径 |
| :--- | :--- |
| 字符计数 | 默认按 Unicode 字符计数，中英文、数字、标点各计 1 个字符 |
| 首尾空格 | 文本字段保存前默认 trim；Textarea 保留正文内部空格与换行 |
| 空字符串 | trim 后为空的选填字段按空值处理；具体传输形式由接口协议定义 |
| 仅空格输入 | 必填字段视为未填写；选填字段视为空值 |
| Emoji | 默认允许；编码、手机号、邮箱、税号等白名单字段不允许 |
| 超长输入 | 默认使用 `maxLength` 阻止继续输入并显示字数；粘贴超长内容不得静默丢失，需提示用户已达上限 |

## 三、模块字段清单的校验章节

每份存在新增/编辑能力的模块字段清单，都应增加“输入与校验约束”章节。所有用户可编辑字段均需列出，主表和明细表不得遗漏。

### 3.1 推荐表格

| 字段 | 必填条件 | 模板编码 | 模块范围/覆盖 | 默认值 | 保存草稿校验 | 提交/确认校验 | 服务端校验 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| [字段名称] | 必填 / 选填 / 条件必填 | 引用本规范模板 | 最大值、特殊字符、跨字段覆盖 | 无 / 具体默认值 | 是否阻断 | 是否阻断 | 唯一性、状态、并发等 |

### 3.2 填写要求

1. “必填”默认表示完成业务提交或确认动作时必须有值，不自动等同于保存草稿必填。
2. 保存草稿必须明确最小可保存条件，不能只写“校验必填项”。
3. 条件必填必须写清触发条件，例如“手工修改含税单价后，改价原因必填”。
4. 唯一性、库存、余额、状态和并发等依赖服务端的信息，必须标明服务端校验。
5. 模块覆盖全局模板时，必须写出覆盖内容和原因，不得只写“特殊处理”。

## 四、主 PRD 的业务校验

以下规则不属于单字段模板，应写入模块主 PRD：

| 规则类型 | 典型示例 |
| :--- | :--- |
| 跨字段 | 期望交货日期不得早于订单日期 |
| 跨行 | 至少一行有效商品；同一商品是否允许重复 |
| 数量关系 | 累计执行数量不得超过订单数量 |
| 金额关系 | 汇总金额等于明细金额之和，允许约定尾差 |
| 条件必填 | 修改默认价格后必须填写改价原因 |
| 状态约束 | 只有草稿态允许编辑关键字段 |
| 动作约束 | 提交、审核、作废、确认前的完整前置条件 |
| 并发与幂等 | 数据已被修改、重复点击、重复提交的处理 |

每条业务校验应包含：规则 ID、触发动作、判断条件、是否阻断、失败文案和必要的后置影响。

## 五、Demo PRD 的前端可执行规格

新增/编辑页 Demo PRD 至少包含以下四部分。

### 5.1 字段输入约束清单

| 字段 | 控件 | 模板/限制 | 输入行为 | 校验时机 | 错误提示位置 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| [字段名称] | Input / NumberInput / Select 等 | 模板编码及模块覆盖 | `maxLength`、过滤、格式化、是否可清空 | 输入 / 失焦 / 选择完成 / 保存 / 提交 | 字段下方 / 单元格 / Toast |

Demo PRD 只转写字段清单和主 PRD 的已确认规则，不重新定义字段本体。

### 5.2 校验触发纪律

| 层级 | 时机 | 页面行为 |
| :--- | :--- | :--- |
| 输入限制 | 用户输入过程中 | 限制长度、字符、数值精度和范围；不在每次按键时主动弹出新的错误 |
| 单字段校验 | 失焦或选择完成 | 检查格式、trim 后空值和轻量规则，在字段附近展示错误 |
| 保存草稿 | 点击保存 | 按字段清单执行最小可保存校验，展示本次动作涉及的全部错误 |
| 提交/确认 | 点击提交、确认等业务动作 | 执行完整字段和业务校验，阻断动作并展示全部错误 |
| 纠错 | 修改已有错误字段 | 仅重新检查并清除该字段当前错误，不提前报出无关新错误 |
| 服务端返回 | 请求失败 | 优先映射到具体字段或明细单元格；无法映射时使用 Toast 或页面级提示 |

### 5.3 错误展示规则

| 场景 | 规则 |
| :--- | :--- |
| 主表字段错误 | 控件红框，字段下方固定区域展示具体文案 |
| 明细单元格错误 | 单元格红框；使用气泡、悬停或行级错误区展示文案，避免挤压列宽 |
| 多处错误 | 阻断动作；提示“共 N 处需修正，请查看标红字段”；滚动并聚焦首个错误 |
| 不可见区域错误 | 自动展开折叠区域或切换到对应 Tab 后再定位 |
| 服务端字段错误 | 映射到对应字段；保留用户已输入内容 |
| 页面级业务错误 | 使用 Alert、Modal 或 Toast，文案说明原因和下一步处理方式 |
| 未保存离开 | 页面存在修改时二次确认 |

错误文案必须具体，不得只写“输入有误”“字段不满足条件”。明细错误建议使用“第 {行号} 行·{字段名称}：{原因}”。

### 5.4 页面验收清单

至少覆盖：

- 必填字段为空时，保存草稿和提交动作分别按规则处理。
- 字符达到最大长度后不能继续输入，并显示准确计数。
- 非法字符、错误格式、数值越界和小数精度均有明确反馈。
- 条件必填在触发条件成立后生效，条件撤销后按规则清除。
- 明细行错误能定位到具体行和单元格。
- 多处错误一次性展示，页面能定位首个错误。
- 服务端返回的字段错误能正确映射，用户输入不丢失。
- 禁用主数据不可新选，历史数据按模块兼容规则展示。
- 并发冲突、重复提交和网络失败有明确反馈。

## 六、主数据示例：客户新增/编辑

以下内容仅演示模板用法，具体字段和规则以客户模块字段清单为准。

### 6.1 字段绑定示例

| 字段 | 必填条件 | 模板编码 | 模块覆盖示例 | 校验时机 | 错误提示示例 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 客户编码 | 按模块规则 | `CODE_50` | 系统生成时只读；手工编码时校验唯一性 | 失焦、保存 | 客户编码已存在，请重新填写 |
| 客户名称 | 必填 | `NAME_100` | 无 | 失焦、保存 | 请填写客户名称 |
| 联系电话 | 选填 | `PHONE_20` | 无 | 失焦、保存 | 请输入正确的联系电话 |
| 邮箱 | 选填 | `EMAIL_100` | 无 | 失焦、保存 | 请输入正确的邮箱 |
| 地址 | 选填 | `ADDRESS_200` | 无 | 输入、保存 | 地址不能超过 200 个字符 |
| 统一社会信用代码 | 按模块规则 | `TAX_ID_30` | 格式和唯一性必须由客户模块显式确认 | 失焦、保存 | 请输入正确的统一社会信用代码 |
| 备注 | 选填 | `REMARK_500` | 无 | 输入、保存 | 备注不能超过 500 个字符 |

### 6.2 子表示例

联系人、收货地址等子表必须逐字段定义，不得只写“联系人必填”或“地址必填”。错误定位示例：

```text
第 2 行·联系人姓名：请填写联系人姓名
第 2 行·联系电话：请输入正确的联系电话
```

默认联系人、默认地址等唯一性属于跨行规则，应写入客户主 PRD，并在 Demo PRD 中转写为页面行为。

## 七、业务单据示例：销售订单新增/编辑

以下内容仅演示业务单据的校验结构，具体数值上限和业务裁定以销售订单字段清单及主 PRD 为准。

### 7.1 字段绑定示例

| 字段 | 必填条件 | 模板编码 | 模块覆盖示例 | 保存草稿 | 提交审核 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 客户 | 必填 | `REFERENCE_ACTIVE` | 仅允许启用客户 | 按销售订单最小保存条件 | 必须有值且状态可用 |
| 发货仓库 | 必填 | `REFERENCE_ACTIVE` | 仅允许启用仓库 | 按销售订单最小保存条件 | 必须有值且状态可用 |
| 订单日期 | 必填 | `DATE` | 默认当天 | 按销售订单最小保存条件 | 必须为合法日期 |
| 期望交货日期 | 选填 | `DATE` | 非空时不得早于订单日期 | 校验已填写值 | 校验已填写值 |
| 备注 | 选填 | `REMARK_200` | 无 | 校验长度 | 校验长度 |
| 跟单备注 | 选填 | `REMARK_500` | 无 | 校验长度 | 校验长度 |
| 明细·商品 | 每个有效行必填 | `REFERENCE_ACTIVE` | 仅允许启用商品 | 校验已存在明细行 | 每行必须有值且状态可用 |
| 明细·订货数量 | 每个有效行必填 | `INTEGER_POSITIVE` | 最大值由销售订单字段清单确认 | 校验已填写值 | 每行必须合法 |
| 明细·含税单价 | 每个有效行必填 | `AMOUNT_2_POSITIVE` | 最大值由销售订单字段清单确认 | 校验已填写值 | 每行必须合法 |
| 明细·改价原因 | 条件必填 | `SHORT_TEXT_100` | 手工改价后是否强制必填由销售订单规则裁定 | 按已确认规则 | 按已确认规则 |

### 7.2 明细错误示例

```text
第 1 行·订货数量：请输入大于 0 的整数
第 3 行·含税单价：含税单价必须大于 0，且最多保留 2 位小数
第 3 行·改价原因：修改价格后必须填写改价原因
```

### 7.3 保存草稿与提交审核

业务单据不得默认保存和提交共用同一套校验：

| 动作 | 校验目标 |
| :--- | :--- |
| 保存草稿 | 保证数据达到模块规定的最小可保存条件，并校验所有已填写值的格式和范围 |
| 保存并提交 / 提交审核 | 在草稿校验基础上，执行完整必填、跨字段、跨行、主数据状态和业务规则校验 |

最小可保存条件必须由模块字段清单或主 PRD 明确，本规范不替具体单据作业务裁定。

## 八、AI 生成与交叉走查清单

### 8.1 生成前

```text
□ 阅读本全局规范
□ 阅读模块字段清单，列出所有可编辑字段和明细字段
□ 为字段绑定全局模板，记录模块覆盖和待确认项
□ 阅读主 PRD，提取保存、提交、跨字段、跨行、状态和并发规则
```

### 8.2 生成 Demo PRD

```text
□ 逐字段输出控件、输入限制、校验时机和错误位置
□ 分开描述保存草稿与提交/确认动作
□ 明细错误可定位到具体行和单元格
□ 定义多错误汇总、首错定位和服务端错误映射
□ 输出可直接走查的校验验收清单
```

### 8.3 交叉走查

| 检查项 | 判断标准 |
| :--- | :--- |
| 字段完整性 | 所有用户可编辑字段均有模板或明确规则 |
| 权威一致性 | 必填性、枚举、范围与字段清单一致 |
| 业务一致性 | 保存、提交、跨字段和状态规则与主 PRD 一致 |
| 页面可执行性 | Demo PRD 明确控件、时机、错误位置和反馈文案 |
| 明细可定位性 | 子表错误能定位到行和单元格 |
| 边界完整性 | 空值、超长、最小值、最大值、精度、禁用数据均有口径 |
| 服务端兜底 | 唯一性、状态、库存、并发等服务端规则未被遗漏 |

## 九、常见误区

| 误区 | 正确做法 |
| :--- | :--- |
| 在 Demo PRD 重新定义字段枚举和必填性 | 以字段清单为准，Demo PRD 只做页面转写 |
| 每个模块复制一套通用正则和错误文案 | 引用本规范模板，仅声明模块覆盖 |
| 只写“提交前校验必填” | 逐字段写模板、范围、时机和错误反馈 |
| 保存草稿与提交审核使用同一套校验 | 分别定义最小保存条件和完整提交条件 |
| 明细只写“至少一行且字段必填” | 对每个明细字段逐行定义，并支持行/单元格定位 |
| 只做前端校验 | 服务端必须再次校验业务规则、唯一性、状态和并发 |
| 最大值未确认时由 AI 自行补值 | 标记待确认，由模块字段清单定稿 |
| 服务端失败只显示“操作失败” | 映射字段错误；页面级错误说明原因和下一步 |
