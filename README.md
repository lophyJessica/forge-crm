# Forge CRM（升级版框架 · 0913test 分支）

> **仓库定位**：Forge CRM 是线索-商机-客户-合同获客 CRM 的**产品知识库 + 前端原型**仓库，不是纯代码工程。结构对齐维他命 QS-JXC-Project 的分层项目框架（01~99），并用 `prototype-annotation` 原型标注闭环承接"PRD→页面→评审"。
>
> **本测试分支说明**：`0913test` 分支承载项目框架升级（把原有 context/prompt/prd-docs 扁平结构升级为 QS-JXC 式分层 + 版本化），`main` 保持旧结构不动。合并回 main 前先在此分支验证。

## 权威源与冲突处理（QS-JXC 式分层）
- 跨模块口径 → `01-全局背景信息/`；跨角色流程→业务流程文件；跨单据处理→系统单据流程。
- 字段名称/类型/来源/枚举/字段级约束 → **字段清单详细稿 TSV**（确认后为唯一源）。
- 模块内状态/动作/业务规则/回写/异常 → **业务 PRD**；页面结构/控件/显隐/校验时机/反馈 → **前端 Demo PRD** + `07-UI规范库/`。
- 冲突先列文件证据+影响范围；未确认的标"待确认"，用户拍板后再同步权威源与下游。

## 文档与变更工作方式
- 动手前先判断本次改变的是业务/字段/页面/方法论/代码，只读相关权威资料。
- 传播方向：字段变化先改详细稿 TSV → 查业务PRD/骨架/DemoPRD/原型；状态动作变化先改业务PRD → 查字段清单+页面；页面变化改 DemoPRD/UI规范/原型，不反向改业务口径。
- 精准修改，不顺手重构无关内容；TSV 保持列数与表头，不增加说明行。

## 前端原型开发
前端命令均在 `99-产品原型prototype/` 执行：`npm install` / `npm run dev` / `npm run build` / `npm run preview`。分层、组件复用、命名以子目录 AGENTS.md 与 `src/docs/UI-DESIGN-GUIDE.md` 为准。不提交 node_modules/dist/.env*。

## 验证
- 文档：查相对链接、术语、状态编号、旧口径残留；流程查 Mermaid。
- 字段清单：查表头列数、枚举、必填性、引用、下游投影。
- 前端：至少 `npm run build`；页面/路由变化还要 `npm run dev` 人工走查。
- 提交：`git diff --check` + 简洁 Conventional Commit（`docs:`/`feat:`/`chore:`）。
