# 拜访计划 Demo：列表页

> **版本**：V2.0 | 2026-08-13  
> **页面路由**：`/crm/visits`  
> **页面目标**：让销售、主管快速识别待执行、超时、未到访和异常拜访，并从列表进入合法动作。

## 1. 页面布局

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 拜访计划                                  [新建拜访]                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ 关键词 [编号/标题/关联对象] [搜索]  状态 [全部⌄]  负责人 [全部⌄]              │
│ 拜访方式 [全部⌄]  计划时间 [日期范围]  异常 [全部⌄]  [重置]                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ 今日待办 12    超时待处理 3    未到访 5    跟进待生成 1                       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 编号/标题 │ 关联对象 │ 方式 │ 计划时间 │ 签到时间 │ 负责人 │ 状态/结果 │ 操作 │
│ VS...0001 │ OPP001  │ 上门 │ 08-13... │ 08-13... │ 张三   │ 已签到    │ 详情 │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 顶部操作

| 控件 | 交互与规则 |
|---|---|
| `新建拜访` Button | 打开新增页；创建结果固定为 `PLANNED + NOT_STARTED`；无客户 ACTIVE 校验通过不可提交。 |
| 关键词 Input | 支持 `visitId`、`title`、`relatedObjectNameSnapshot` 展示查询；提交后端仍按稳定 ID 查询。 |
| `状态` Select | 筛选 `PLANNED`、`CHECKED_IN`、`COMPLETED`、`CANCELLED`；执行结果另提供筛选。 |
| `负责人` UserSelect | `SALES_REP` 只能看到自己；`SUPERVISOR`/`ADMIN` 可查看团队/全量。 |
| `计划时间` DateRangePicker | 以 `Asia/Shanghai` 展示和查询。 |
| `异常` Select | `OVERTIME`、`MISSED`、`CHECK_IN_FAILED`、`CUSTOMER_NO_SHOW`、`FOLLOW_UP_PENDING`。 |
| `重置` Button | 清空筛选并重新查询，不改变任何拜访数据。 |

## 3. 列表字段与展示规则

| 列 | 字段 | 展示规则 |
|---|---|---|
| 编号/标题 | `visitId`、`title` | 编号单行；标题最多两行，点击进入详情。 |
| 关联对象 | `relatedObjectType`、`relatedObjectId`、`relatedObjectNameSnapshot` | 展示类型 Tag + 名称；对象已停用/输单显示快照状态，不以名称替代 ID。 |
| 拜访方式 | `visitMethod` | `ONSITE` 上门、`PHONE` 电话、`VIDEO` 视频。 |
| 计划时间 | `plannedStartAt`、`plannedEndAt` | `YYYY-MM-DD HH:mm`；超过截止且未签到显示“已超时”。 |
| 签到时间 | `checkInAt` | 未签到显示 `—`；已签到后取消仍展示实际签到时间。 |
| 负责人 | `assigneeId` | 展示人员姓名；负责人转交后显示当前负责人。 |
| 状态/结果 | `primaryStatus`、`executionResult`、`executionException` | 主状态 Tag + 结果 Tag；异常用黄色提示图标，不覆盖主状态。 |
| 下一步 | `nextFollowUpAt`、`followUpRecordId` | 有跟进显示时间；`FOLLOW_UP_PENDING` 显示“重试生成”。 |
| 更新时间 | `updatedAt` | 统一时区格式，用于识别并发变更。 |

## 4. 行操作矩阵

| 当前数据 | OWNER | SUPERVISOR/ADMIN |
|---|---|---|
| `PLANNED + NOT_STARTED` 未超时 | 详情、编辑、签到、取消、改期 | 详情、编辑、签到、代签、取消、改期、转交、主管修正 |
| `PLANNED + NOT_STARTED` 已超时 | 详情、标记未到访、改期、取消 | 详情、标记未到访、改期、取消、主管修正 |
| `PLANNED + MISSED` | 详情、重新计划、取消 | 详情、重新计划、取消、主管修正 |
| `PLANNED + RESCHEDULED` | 详情 | 详情、审计 |
| `CHECKED_IN` | 详情、保存反馈、完成 | 详情、完成、已签到后取消、代为补充、主管修正 |
| `COMPLETED` | 详情 | 详情、补充反馈、退回反馈、主管修正 |
| `CANCELLED` | 详情 | 详情、审计 |

规则：状态变化按钮不进入编辑表单；所有签到、完成、取消、改期、标记未到访动作弹出二次确认；动作成功显示 Toast，失败提供具体错误和可安全重试按钮。

## 5. 状态、Tag 与空态

| 状态 | Tag |
|---|---|
| `PLANNED` | 蓝色 `#1677FF` |
| `CHECKED_IN` | 橙色 `#FA8C16` |
| `COMPLETED` | 绿色 `#52C41A` |
| `CANCELLED` | 红色 `#F5222D` |
| `MISSED` | 紫色 `#722ED1` |
| `RESCHEDULED` | 灰色 `#8C8C8C` |
| 异常 | 黄色 `#FAAD14` |

- 初次加载：表格骨架屏，禁止短暂显示错误空态。
- 无数据：显示“暂无拜访计划”，提供“新建拜访”按钮；不显示删除入口。
- 无筛选结果：显示“未找到匹配拜访”，提供“重置筛选”。
- ERP 状态查询失败：保留列表快照，顶部显示“部分客户状态待同步”，涉及新建/签到时在提交前再次校验。
- 无权限：显示“暂无查看权限”，不展示可猜测的对象名称或操作按钮。

## 6. 交互验收

| 编号 | Given | When | Then |
|---|---|---|---|
| L01 | 未签到计划 | 查看列表 | 签到时间显示 `—`。 |
| L02 | 已签到后取消计划 | 查看列表 | `CANCELLED` 红 Tag 旁显示“已签到后取消”，签到时间仍可见。 |
| L03 | 超过计划结束时间且无签到 | 刷新列表 | 只出现“已超时待处理”，不自动变为 `MISSED`。 |
| L04 | `FOLLOW_UP_PENDING` | 点击“重试生成” | 沿用幂等键；成功后显示跟进编号，失败保留异常。 |
| L05 | `COMPLETED` 且当前为销售 | 查看行操作 | 无编辑、取消、签到按钮；仅详情。 |
