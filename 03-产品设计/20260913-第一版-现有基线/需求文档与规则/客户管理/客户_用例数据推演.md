# 客户_用例数据推演

> **版本**：V1.0 | 2026-08-13
> **用途**：验证客户模块 ERP SSOT、CRM 只读快照、双标识、生命周期/同步状态分离及关联对象处理规则。
> **关联文档**：《客户主PRD》《客户字段清单》《客户_Demo_列表页》《客户_Demo_详情页》

## 1. 统一数据约束

- `crmCustomerId`：CRM 快照记录标识，只在 CRM 内部关联商机、合同、拜访、跟进。
- `erpCustomerId`：ERP 正式客户档案标识，跨系统请求、订单同步和 ERP 事件统一使用。
- `sourceVersion`：ERP 来源版本；`sourceEventId`：来源事件唯一标识。旧版本或重复事件不得覆盖新快照。
- `lifecycleStatus`：`PROSPECT/ACTIVE/DISABLED/MERGED`；`syncStatus`：`PENDING_RECEIVE/VALIDATING/AVAILABLE/SYNC_FAILED`，两套状态不混用。
- 公司名称只用于展示和搜索，禁止作为关联键。
- 客户基础字段 ERP 为 SSOT，CRM 只创建和展示只读快照；客户管理页没有“新增客户”入口。

## 2. 用例推演

### UC-01 正常建档与首次同步

| 项目 | 推演 |
|------|------|
| 输入标识 | 线索 `leadId=L-1001`；ERP 返回 `erpCustomerId=ERP-C-1001`；CRM 生成 `crmCustomerId=CRM-S-1001` |
| 来源版本 | `sourceVersion=202608130001` |
| 事件ID | `sourceEventId=evt-customer-created-1001` |
| 状态变化 | 线索提交 ERP 建档申请 → ERP 创建正式档案 → `PENDING_RECEIVE → VALIDATING → AVAILABLE`；生命周期为 `ACTIVE` |
| 关联对象处理 | 商机、合同、拜访、跟进内部关联 `CRM-S-1001`；跨系统请求使用 `ERP-C-1001` |
| 结论 | CRM 只在建档成功事件后创建只读快照，双标识和同步元数据可审计 |

### UC-02 建档成功但首次快照失败

| 项目 | 推演 |
|------|------|
| 输入标识 | `leadId=L-1002`、`erpCustomerId=ERP-C-1002`；ERP 建档成功但 CRM 写入失败 |
| 来源版本 | `sourceVersion=202608130002` |
| 事件ID | `sourceEventId=evt-customer-created-1002` |
| 状态变化 | CRM 创建待绑定任务；同步状态为 `SYNC_FAILED`，不伪造 `crmCustomerId` 客户快照 |
| 关联对象处理 | 禁止新建商机、合同、拜访、跟进；线索显示“ERP 已建档待同步” |
| 结论 | 管理员只能点击“重试同步”，成功后再建立 CRM 快照绑定 |

### UC-03 重复建档成功事件

| 项目 | 推演 |
|------|------|
| 输入标识 | 同一 `erpCustomerId=ERP-C-1003`、同一建档结果重复到达 |
| 来源版本 | `sourceVersion=202608130003` |
| 事件ID | 两次均为 `sourceEventId=evt-customer-created-1003` |
| 状态变化 | 首次正常进入 `AVAILABLE`；第二次按 `sourceEventId` 幂等返回，不新建快照或客户对象 |
| 关联对象处理 | 只保留一个 `crmCustomerId`；不重复生成商机、合同、拜访或跟进绑定 |
| 结论 | 事件ID是去重依据，不能以公司名称或重复消费次数判断是否为新客户 |

### UC-04 新旧版本乱序到达

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1004` 已有 `crmCustomerId=CRM-S-1004`；版本 12 先到，版本 11 后到 |
| 来源版本 | 先 `sourceVersion=12`，后 `sourceVersion=11` |
| 事件ID | `evt-customer-update-1004-v12`、`evt-customer-update-1004-v11` |
| 状态变化 | 版本 12 写入 `AVAILABLE`；版本 11 被拒绝，不回退 `snapshotVersion` |
| 关联对象处理 | 所有关联对象继续使用原双标识，不因旧事件重放而复制或解绑 |
| 结论 | 以来源版本优先，事件ID辅助审计和幂等；旧事件必须有拒绝记录 |

### UC-05 同步失败与重试

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1005`、现有最近成功快照 `crmCustomerId=CRM-S-1005` |
| 来源版本 | 新事件 `sourceVersion=20` 高于当前版本 19 |
| 事件ID | `sourceEventId=evt-customer-update-1005-v20` |
| 状态变化 | `AVAILABLE → PENDING_RECEIVE → VALIDATING → SYNC_FAILED`；保留版本 19，记录 `lastAttemptAt/retryCount/syncErrorCode` |
| 关联对象处理 | 可查看旧快照；可进入新建商机、拜访、跟进；合同需跳转商机详情发起，所有提交前重新校验 ERP 有效性和版本 |
| 结论 | 管理员点击重试是动作按钮；成功后版本 20 替换旧快照，失败不清空旧数据 |

### UC-06 ERP 停用客户

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1006`、`crmCustomerId=CRM-S-1006` |
| 来源版本 | `sourceVersion=30`，高于当前版本 29 |
| 事件ID | `sourceEventId=evt-customer-disabled-1006` |
| 状态变化 | 生命周期 `ACTIVE → DISABLED`；同步处理状态不改名为“ERP停用”，页面单独展示停用状态 |
| 关联对象处理 | 商机历史可查但不可推进；合同只读不自动作废；拜访新建/改期新单/新签到阻断，已签到可完成并生成跟进作为历史事实收口；跟进禁止新增；订单继续只读同步 |
| 结论 | `DISABLED` 是对新业务不可用状态，不是终态；CRM 不提供停用或恢复按钮 |

### UC-07 ERP 合法恢复

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1007`、现状为 `DISABLED` |
| 来源版本 | 停用版本 40；启用事件版本 41，高于当前版本 |
| 事件ID | `sourceEventId=evt-customer-enabled-1007-v41`，全局唯一且未处理 |
| 状态变化 | `DISABLED → PENDING_RECEIVE → VALIDATING → AVAILABLE`；生命周期恢复为 `ACTIVE` |
| 关联对象处理 | 历史对象不自动回滚；恢复完成且快照可用后，按权限重新开放新商机、合同、拜访和跟进 |
| 结论 | 恢复来自 ERP 合法启用事件；CRM 页面没有“恢复客户”按钮 |

### UC-08 ERP 恢复事件非法或失败

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1008`、现状为 `DISABLED` |
| 来源版本 | 启用事件缺版本、版本 50 低于当前停用版本 51，或字段校验失败 |
| 事件ID | 缺失、重复，或 `sourceEventId=evt-customer-enabled-1008-old` 已处理 |
| 状态变化 | 保持生命周期 `DISABLED`；不直接跳到 `ACTIVE`，错误进入同步审计/重试任务 |
| 关联对象处理 | 继续禁止新业务和新增跟进；历史对象保持只读 |
| 结论 | 只有版本更高、事件新且 payload 合法的 ERP 启用事件才可恢复 |

### UC-09 ERP 合并客户

| 项目 | 推演 |
|------|------|
| 输入标识 | `sourceErpCustomerId=ERP-C-1009-A`、`targetErpCustomerId=ERP-C-1009-B` |
| 来源版本 | `sourceVersion=60` |
| 事件ID | `sourceEventId=evt-customer-merge-1009` |
| 状态变化 | 源客户生命周期变为 `MERGED`，保存 source/target 映射；源快照只读 |
| 关联对象处理 | 历史商机、合同、拜访、跟进保留原 `crmCustomerId` 和 `erpCustomerId`，支持跳转主客户；新业务只关联 target |
| 结论 | CRM 不执行合并，不删除历史，不把历史对象静默改绑 |

### UC-10 停用客户关联对象与恢复后处理

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1010`、`crmCustomerId=CRM-S-1010`；已存在商机、合同、拜访、跟进和订单 |
| 来源版本 | 停用版本 70；恢复版本 71 |
| 事件ID | `evt-customer-disabled-1010`、`evt-customer-enabled-1010-v71` |
| 状态变化 | 先进入 `DISABLED`；恢复按 `PENDING_RECEIVE → VALIDATING → AVAILABLE` 回到 `ACTIVE` |
| 关联对象处理 | 停用期间按矩阵处理：商机不可推进、合同只读；拜访新建/改期新单/新签到阻断，已签到可完成并生成跟进作为历史事实收口；跟进禁止新增、订单只读同步；恢复后不自动回滚，按权限重新操作 |
| 结论 | 停用影响新业务可用性，不改变历史对象事实；恢复只开放能力，不伪造业务状态 |

### UC-11 无成功快照的同步中状态

| 项目 | 推演 |
|------|------|
| 输入标识 | `erpCustomerId=ERP-C-1011`，尚未产生成功 `snapshotVersion` |
| 来源版本 | `sourceVersion=80` |
| 事件ID | `sourceEventId=evt-customer-created-1011` |
| 状态变化 | `PENDING_RECEIVE → VALIDATING` 或失败进入 `SYNC_FAILED`；无 `lastSuccessfulSyncAt` |
| 关联对象处理 | 页面只显示待同步/错误，不展示伪造基础字段；禁止新建商机、合同、拜访、跟进 |
| 结论 | “同步中”不是一律可用；可用性取决于是否存在最近成功快照 |

### UC-12 无权限深链接

| 项目 | 推演 |
|------|------|
| 输入标识 | 用户访问 `/accounts/{crmCustomerId}`，但不在该客户数据权限范围 |
| 来源版本 | 不读取或展示来源版本 |
| 事件ID | 不创建业务事件 |
| 状态变化 | 返回 `403`，不改变客户生命周期或同步处理状态 |
| 关联对象处理 | 不返回公司名称、手机号、ERP 编号、商机、合同、拜访、跟进或订单摘要 |
| 结论 | 深链接必须重新执行数据权限校验，403 不泄露客户存在性和敏感标识 |

## 3. 验收结论

- [ ] 每个用例同时记录双标识、来源版本、事件ID、状态变化、关联对象处理和结论。
- [ ] CRM 不产生客户主数据，不以公司名称作关联键。
- [ ] 生命周期状态与同步处理状态分离。
- [ ] ERP 停用可由合法启用事件恢复，失败保持停用。
- [ ] ERP 合并保留历史映射，源客户只读，新业务仅关联主客户。
