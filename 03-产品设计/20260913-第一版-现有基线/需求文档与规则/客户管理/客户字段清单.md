## 五、跨模块关联与展示规则

### 5.1 标识使用规则

| 关联对象/场景 | CRM 内部关联字段 | 跨系统请求字段 | 权威来源与约束 |
|--------------|------------------|----------------|----------------|
| CRM 商机 | `crmCustomerId` | 需要调用 ERP 时使用 `erpCustomerId` | 商机 SSOT 在 CRM；禁止用公司名称关联 |
| CRM 合同 | `crmCustomerId` | 需要调用 ERP 时使用 `erpCustomerId` | 合同业务字段引用合同字段清单；禁止用公司名称关联 |
| CRM 拜访 | `crmCustomerId` | 需要调用 ERP 时使用 `erpCustomerId` | 拜访业务字段引用拜访字段清单；禁止用公司名称关联 |
| CRM 跟进 | `crmCustomerId` | 需要调用 ERP 时使用 `erpCustomerId` | 跟进保留来源对象标识；禁止用公司名称关联 |
| ERP 订单摘要 | `erpCustomerId` | `erpCustomerId` | 订单 SSOT 在 ERP；CRM 只读同步摘要 |
| ERP 建档/变更/合并请求 | 不适用 | `erpCustomerId`及事件字段 | 跨系统请求必须携带 ERP 标识、来源版本和 `sourceEventId` |

CRM 内部业务表可以保存 `crmCustomerId` 作为外键，并冗余保存最近一次有效的 `erpCustomerId` 供审计；任何跨系统请求、ERP 订单查询或事件匹配必须使用 `erpCustomerId`。公司名称只用于展示和检索，禁止作为关联键。

### 5.2 生命周期与同步状态展示

- `ACTIVE` + `syncStatus=AVAILABLE`：客户可用，按权限展示关联业务动作。
- `ACTIVE` + 同步中：有最近成功快照时可继续业务，但提交前重新校验；无成功快照时禁止新建关联业务。
- `ACTIVE` + `SYNC_FAILED`：沿用最近成功快照，展示旧版本和同步异常；提交前重新校验。
- `DISABLED`：对新业务不可用但可恢复；保留历史关联，只读展示，不提供 CRM 恢复按钮。
- `MERGED`：旧客户标识只读，仅用于历史查询，新业务必须关联合并后的主客户。

## 六、展示规则

- 列表排序为本模块例外：第一优先级为进行中商机优先，第二优先级为 ERP 客户创建时间倒序；用户主动选择排序时以用户排序为准。该规则覆盖通用创建时间排序规范。
- 流失风险颜色：高风险红色、中风险黄色、低风险绿色、待计算灰色、失败且有历史结果沿用历史风险颜色并增加时钟标识、失败且无历史结果显示灰色“暂不可用”、停用客户显示灰色停用标识。
- 风险 Tab、AI流失风险 Select 与 ERP同步标识 Select 默认取交集；“全部客户”不增加风险条件。条件优先级为数据权限 > 客户生命周期可用性 > 风险 Tab/风险 Select > 同步标识，任何条件均不覆盖其他条件。
- 风险 Tab 与 Select 结果冲突时返回空结果并提示重置，不以后操作条件覆盖先前条件。
