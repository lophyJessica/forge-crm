# 02 · 页面模板与实例映射

> **定位**：Forge-CRM 各类页面的**标准结构模板** + 已实现实例映射。做新页面时按模板搭结构，不自由布局。
> **依据**：从 `src/pages/` 既有实现（LeadsList / ContractForm / LeadDetail 等）提炼固化，不是新拟。

## 一、列表页（list）

标准结构（自上而下）：

```
页面头部（标题 + 右按钮组：新建/批量导入）
状态 Tabs（全部/待分配/跟进中/我的线索… 或模块级页签）
筛选区（Card：关键词 + 各筛选字段 + 负责人 + 创建日期区间 + 重置/查询）
批量工具条（选中后出现：已选 N 项 + 批量作废 + 取消选择）
数据表格（Card overflow-hidden）
  表头（列 + 可排序）
  行（Checkbox + 各展示字段 + 状态Badge + 行操作列固定右侧）
分页/底部（每页条数 + 页码）
```

关键规则：
- 表格 Card 用 `Card className="overflow-hidden"`，行操作列固定右侧可横向滚动。
- 状态标签用 `Badge`（业务名 + 英文枚举仅辅助）。
- 操作入口按当前状态+权限显隐（按钮来自业务PRD状态-操作矩阵）。

**实例**：LeadsList（`data-anno="leads-table-fields"` Card = 表格）。

## 二、带 Tab 子视图的列表（list_tab_subview）

公海（LeadPool）= 线索列表页的 `HIGHSEAS` 子视图，复用过滤/表格结构，但字段侧重入池时间/入池类型/放弃原因，操作侧重认领。
规则：共享外层，子视图独立字段/操作；标注看主模块 PRD + 子视图独立 PRD。

## 三、表单页（form，新增/编辑共用）

标准结构：

```
页面头部（标题「新建线索/编辑线索」+ 面包屑）
表单 Card（grid-cols-* 分组字段）
  基本信息（来源Select / 公司Input / 联系人 / 手机号 / 邮箱）
  业务信息…
  明细区（单据类有多行明细子表）
固定底部操作区（border-t 白底：保存草稿 / 提交/下一步 / 取消）
```

关键规则：
- 条件分组用 `Card`；字段用 `grid grid-cols-1 md:grid-cols-4 gap-5` 响应式降列。
- 校验时机/反馈按字段清单 + Demo PRD（失焦/提交时）。
- 底部操作区 `fixed bottom-0`（`ContractForm` 已用 `fixed bottom-0 left-0 right-0 z-40 bg-white border-t`）。

**实例**：LeadForm / ContractForm / OppForm / VisitForm / TargetForm。

## 四、详情页（detail）

标准结构：

```
页面头部（标题 + 状态 Badge + 操作按钮：编辑/跟进/转客户/放弃）
基本信息区（只读字段展示）
业务区（跟进记录 / 关联明细 / 关联单）
制单信息（创建人/创建时间/最后修改）
```

规则：只读展示为主；操作来自状态-操作矩阵；关联区承载"线索→商机/合同/拜访"关系。

**实例**：LeadDetail / CustomerDetail / ContractDetail / OppDetail / VisitDetail。

## 五、Dashboard（主工作台）

经营概览卡片 + 待办 + 主链路入口。落地见现有 Dashboard 页面，后续随 PRD 细化。

## 变化规则
页面结构/字段位置要改 → 改本文件 + 对应 Demo PRD + 原型；不改字段TSV和业务PRD（除非涉及字段事实/业务规则）。
