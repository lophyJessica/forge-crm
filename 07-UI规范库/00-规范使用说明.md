# Forge-CRM UI 规范库 · 00 规范使用说明

> **定位**：本目录是 Forge-CRM 前端的 **UI 权威源**。页面实现遵循本库 + 该页面的 Demo PRD，不从 Mock 或页面反向发明规则。
> **技术栈事实**：React + TypeScript + Tailwind CSS v4（CSS-first，token 在 `src/index.css`）+ shadcn 风格组件（`src/components/ui/`）。
> **与上游关系**：页面结构以 Demo PRD 为准，UI 表现遵循本规范库；字段来自字段清单 TSV，业务规则来自业务 PRD。UI 层不得篡改这三者的口径。

## 文件结构与用途

| 文件 | 内容 |
| --- | --- |
| `00-规范使用说明.md` | 本文件：定位 + 使用方式 |
| `01-系统级约束与Token基线.md` | 颜色/尺寸/圆角/断点/字体等系统级 token（**唯一来源**） |
| `02-页面模板与实例映射.md` | 各类页面（列表/表单/详情/Dashboard）的标准结构 + 已实现实例 |

| `04-状态权限与异常规则.md` | 空态/加载/错误/权限/危险动作的统一表现 |
| `05-AI协作输入输出模板.md` | 让 AI 生成/改页面的输入输出规范（先出方案/直接出骨架/补异常态） |
| `06-模块契约与原型复刻规范.md` | 每条数据链路（Dexie + erpSync 等）的契约边界，原型不得反向发明 |
| `07-单据页面复刻约定.md` | 单据类页面（新增/编辑/详情）的区划分层与复刻约定 |

## 使用方式（对 AI 生成页面）
1. 先确定页面类型（列表/表单/详情/Dashboard），读 `spec-manifest.json` 看该类型要遵循哪些文件。
2. 颜色/尺寸一律用 `01` 的 token，页面不得散写随机 HEX（除非插图）。
3. 组件用 `src/components/ui/` 的既有封装，不重复造。
4. 状态/权限/异常统一看 `04`；单据类页面再看 `07`；轻量表单看 `08`。
5. 改完遵循 AGENTS.md 的验证门（build + 页面 dev 人工走查）。

## 与 QS-JXC 的关系
本库结构对齐 QS-JXC 的 `07-UI规范库` 分层理念，但 **token 与组件按 Forge-CRM 实际实现（蓝色主调 / slate / shadcn / Tailwind v4）适配**，不照搬 QS-JXC 的 Arco 色板。
