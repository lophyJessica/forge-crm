# 05 · AI 协作输入输出模板

> **定位**：让 AI 生成/修改 Forge-CRM 页面时的输入输出规范。统一"先给边界再给任务"。

## 一、给 AI 生成页面的任务结构（四段式）
```
输入材料：
- 07-UI规范库（本目录，尤其 01 Token + 02 页面模板 + spec-manifest）
- 对应模块：字段清单详细稿TSV / 业务PRD / Demo PRD
- 现有页面（参考锚点：LeadsList 列表 / LeadForm 表单 / LeadDetail 详情）

当前任务：只输出某一页（列表或表单或详情）的前端骨架/Demo实现，不要一次全铺。

权威边界：
- 颜色/尺寸取 01 Token；组件用 src/components/ui/；页面结构按 02 模板。
- 字段来自字段清单TSV；业务规则来自业务PRD；页面交互来自 Demo PRD。
- 不得自造字段、状态、按钮；不得反向从 Mock 发明业务规则。

输出要求：列改动文件 + 影响下游（field TSV / 业务PRD / DemoPRD / 其他页面）。
```

## 二、三种工作方式（按需选）
| 方式 | 用在哪 | 先出什么 |
| --- | --- | --- |
| 先出页面方案 | 结构不清楚 | 页面结构说明（区域/容器/字段分布） |
| 直接出页面骨架 | 结构大概清 | ASCII 线框/骨架 |
| 直接出前端实现 | 结构+交互都清 | 直接改页面代码 |
| 补齐异常态权限态 | 主态已有 | 空态/加载/错误/权限/危险动作（按 04） |

## 三、语言/质感
- 中文输出；专业术语/字段名保留英文原文；emoji 仅审阅标注场景用。
- 先结论后展开：结论 → 依据 → 交付物。
- 避免空洞词（赋能/助力/深化/全面）。
- 复杂逻辑用 Mermaid/表格，不用长段落。

## 四、走查复盘
- 生成后走查：字段是否都在TSV、按钮是否都在状态-操作矩阵、颜色是否取 01 token。
- 问题改源头（源文件），不在聊天窗临时纠正；改一处想上下游。
