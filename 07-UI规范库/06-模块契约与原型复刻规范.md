# 06 · 模块契约与原型复刻规范

> **定位**：Forge-CRM 前端数据与模块契约的**边界**——原型不得反向发明业务规则，数据层/契约层负责什么、不负责什么。
> **依据**：前端 Dexie 数据层 + 页面结构 + AGENTS.md 权威源分层。

## 一、权威源边界（不得越界）
| 事项 | 权威源 | 前端不得 |
| --- | --- | --- |
| 字段定义/枚举/必填 | 字段清单详细稿 TSV | 自造字段、改写枚举 |
| 状态/动作/业务规则 | 业务 PRD | 自造状态/按钮、改状态 |
| 页面结构/控件/交互/反馈 | Demo PRD + 本 07 库 | 自由布局、自造交互 |
| 跨模块关联 | 系统架构/流程 + erpSync 契约 | 臆造接口 |

## 二、数据层契约（Dexie）
- 前端 `src/db.ts` + 各模块 DB（如问卷/线索仓库等）**只承载演示/Mock 数据，不代表数据库设计**。
- 演示状态、局部交互可放 `data/*Workspace` 层（对齐 QS-JXC 理念），但不当作业务事实。
- 新增字段必须先在字段清单 TSV 定义，再进数据层/页面；不可只改前端数据就宣称功能完成。

## 三、erpSync（CRM→ERP 联动）
- CRM 转客户 → ERP 客户档案：**契约以 ERP 侧为准**（对齐 ERP schema v1-v6 全套），前端单向适配。
- 转客户成功才写转化时间；ERP 失败不伪造成功、保留原状态提示重试。

## 四、复刻原则
- 前端按「页面/模块」组织（`src/pages/`），契约按模块（`domain/` / `lib/`）组织；UI 按 03 组件。
- 页面深色如"已注册可访问"以 `src/app` 路由为事实源；未实现的能力明说"未实现"，不补空壳。
- 重构/复刻页面时：保留 `data-anno` 锚点（原型标注依赖）、保留 erpSync/Dexie/路由，不得顺手清掉（见重构保留区）。

## 五、验证
- 改契约/数据/页面后执行 AGENTS.md 验证门：build + 受影响页面 dev 人工走查 + 原型标注回归。
