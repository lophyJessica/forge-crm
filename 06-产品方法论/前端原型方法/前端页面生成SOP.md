# 前端页面生成 SOP

> **定位**：把页面生成从"聊天式试错"收敛为"可重复、可验收"的固定工作流
> **来源**：从既有原型工程的页面生成 SOP 提炼

---

## 1. 总原则

- 先对齐真相源，再写代码
- 先锁定页面契约，再做实现细节
- 先复刻参考骨架，再考虑抽象复用
- 先看运行态，再认定页面完成

---

## 2. 真相源读取顺序

任何页面任务，按以下顺序取上下文：

1. 当前任务对应的 Demo PRD、字段清单
2. 前端原型工程中最相近的已实现页面
3. 通用资产库中的产品设计规范
4. AI 自身通用前端经验

**硬约束**：
- 只要工程已有同类参考页，必须先读它
- 不允许跳过字段清单
- 不允许用通用后台习惯覆盖项目已有模式

---

## 3. 页面任务启动前的 4 项判断

在开始写代码前，先明确：

### 3.1 页面类型
标准列表页 / 标准详情页 / 新增编辑页 / 组合模块

### 3.2 输出范围
只出列表 / 只出详情 / 列表+详情 / 列表+详情+新增编辑

### 3.3 参考来源
有无工程中的参考页面？路径是什么？

### 3.4 交互级别
是否有勾选列？批量操作？列设置？状态Tab？

**这 4 项没想清楚不要开写。**

---

## 4. 页面契约先行

正式落代码前，先锁定页面契约，按下方「页面契约模板」输出一版契约稿。

**适用场景**：新页面生成 / 老页面大改 / 列表+详情组合模块 / 参考页可能与最新 PRD 不一致

**原则**：
- 契约稿只写"页面要实现什么"，不写具体实现代码
- 契约稿来自 PRD、字段清单、参考页，不来自 AI 自行发挥
- 契约稿锁住后再写代码，降低后续返工

### 契约合格标准

一份合格的契约稿，至少满足：

1. 查询字段已经列清楚
2. 表格列顺序已经列清楚
3. 行操作和批量操作已分开写清楚
4. 详情页分区顺序已经写清楚
5. Mock 覆盖要求已经写清楚

如果这 5 件事还不清楚，**不要直接进入代码实现**。

### 契约常见误区

| 误区 | 后果 |
| :--- | :--- |
| 只列字段，不列动作 | 代码阶段最容易漏交互 |
| 只列列表，不列详情 | 列表和详情字段口径脱节 |
| 不写 Mock 契约 | 状态覆盖不足，交互测不起来 |
| 不写风险点 | 复用老页面时漏掉最新 PRD 变更 |

## 5. 标准执行步骤

### Step 1：读取上下文
打开 Demo PRD → 字段清单 → 参考页面 → 设计规范

### Step 2：锁定页面契约
列出查询字段、表格列、操作矩阵、详情分区

### Step 3：搭骨架
先让页面结构正确，不在这一步抢着补复杂业务逻辑

### Step 4：补业务逻辑
查询过滤 → 排序 → 单条/批量操作 → 弹窗确认 → Toast文案

### Step 5：补 Mock 数据
按字段清单枚举生成，按 PRD 状态分布，附状态覆盖统计表

### Step 6：构建与运行态检查
- `npm run build`（或对应构建命令）
- 打开实际页面验证

**只有运行态检查过了，页面才算完成。**

---

## 6. 最容易返工的 8 类问题

1. 只看 PRD，不看字段清单，导致枚举和字段口径错
2. 只看截图，不看参考页代码，导致骨架和节奏错
3. 先做抽象，再让页面适配抽象
4. 只补单条操作，漏掉批量操作
5. build 通过就结束，没做运行态走查
6. Mock 状态覆盖不够
7. 老页面和新 PRD 不一致时没做差异回补
8. 确认按钮用"确定"而非语义化文案
