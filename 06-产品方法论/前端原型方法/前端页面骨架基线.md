# 前端页面骨架基线

> **定位**：定义列表页、详情页、新增编辑页的标准页面结构和交互规则，指导 AI 根据 Demo PRD 生成前端原型页面
> **来源**：从既有原型工程的页面设计基线、页面生成规则中提炼，去掉了具体的 CSS 类名、Design Token 数值和 React 组件路径
> **使用方式**：AI 在生成页面时，先判断页面类型 → 查找对应骨架规则 → 按骨架搭建 → 填充业务逻辑

## 0. 页面类型判断

默认分为三类：

- **标准列表页**：查询区 + 工具条 + 表格 + 分页
- **标准详情页**：标题区 + 信息分区 + 操作区
- **新增/编辑页**：表头表单 + 明细表格 + 操作按钮

如果用户没有明确说明页面类型，AI 根据 Demo PRD 自行判断，不要反问用户。

### 查询区组件映射

| PRD 中的字段类型 | 对应前端组件 |
|----------------|------------|
| 普通文本搜索 | Input |
| 枚举下拉单选 | Select |
| 关联主数据搜索 | SearchableSelect（展示 {Code} {Name}） |
| 日期范围 | DateRangePicker |

### 表格规则

- 勾选列固定左侧，不进入列设置
- 操作列固定右侧，不进入列设置
- 业务列顺序与 Demo PRD 逐列一致
- 空值展示 `-`

## 1. 列表页骨架

### 1.1 固定结构（从上到下）

```
┌─ 页面标题区 + 页面级主操作 ───────────────────┐
│  页面标题 / 新增按钮 / 导入按钮               │
├─ 查询筛选区 ──────────────────────────────────┤
│  常驻筛选项（最多 2 行 × 6 列 = 12 占位）     │
│  展开后附加筛选项                              │
│  右侧操作：展开/收起 → 重置 → 搜索            │
├─ 状态 Tab 区（可选变体）─────────────────────┤
│  全部(134) | 待审核(12) | 已审核(98) | ...     │
├─ 表格工具条 ──────────────────────────────────┤
│  左侧：已选计数 + 批量操作按钮                 │
│  右侧：列设置 / 密度切换等表格级弱操作         │
├─ 表格数据区 ──────────────────────────────────┤
│  表头 / 数据行 / 行内操作                      │
└─ 分页区 ──────────────────────────────────────┘
   共X行数据 / 每页条数 / 上一页下一页 / 跳转
```

### 1.2 查询筛选区规则

- 默认桌面端 **6 列栅格**，最多展示 2 行，总占位 ≤ 12 列
- 超出部分通过"展开/收起"承载
- 右侧操作组固定顺序：**展开/收起 → 重置 → 搜索**
- 日期范围算 **2 列**占位
- 查询区只放筛选条件，**不放业务主动作**
- 批量操作只放工具条，不混进查询区

### 1.3 表格工具条规则

- **全选**放在表格首列表头内，不在工具条重复
- 已选计数和批量操作**同一行**（计数在左、按钮紧随）
- 列设置入口放工具条**右侧**
- 不应机械性给每个页面放"刷新"按钮

### 1.4 行内操作规则

- 优先 2~3 个文字动作，高风险动作进"更多"
- 保留的入口必须有最小可用行为，不允许无反馈的假交互

### 1.5 分页区规则

- 至少包含：总数、每页条数切换、上一页/下一页、跳转
- 默认总数句式：`共X行数据`

### 1.6 状态 Tab 变体

- 适用场景：状态分组是用户最高频切换维度
- 位于查询区之后、表格之前
- 展示"状态名 + 数量"
- 切换后回到第一页
- 点击"重置"时，状态 Tab 同步恢复为默认（通常为"全部"）
- 视觉采用线性下划线式，不用胶囊按钮式

## 2. 详情页骨架

### 2.1 固定结构（从上到下）

```
┌─ 单号标题区 + 页面级主操作 ───────────────────┐
│  单号 / 状态Badge / 关键元信息                 │
│  返回列表 / 编辑 / 提交 / 审核 等操作按钮      │
├─ 卡片化信息区 ────────────────────────────────┤
│  基本信息卡                                    │
│  业务信息卡                                    │
│  结算或补充信息卡                              │
├─ Tab 区 ──────────────────────────────────────┤
│  明细 / 关联单据 / 操作日志 / 审批记录         │
├─ 制单信息区（固定置底）──────────────────────┤
│  创建人 / 创建时间 / 修改人 / 修改时间         │
└───────────────────────────────────────────────┘
```

### 2.2 核心规则

- **详情页不是禁用版表单**——只读字段统一用文本展示，不用 disabled 输入框
- **制单信息固定置底**，商品明细必须在制单信息之上
- **标题区不重复**下方基本信息已有的字段
- 操作按钮统一放在标题区右侧
- "返回列表"放在按钮组**最左侧**
- 不该出现的操作直接不展示（而非 disabled）
- 系统账号展示为 **`System`**（首字母大写）
- 无 PRD 依据时禁止加说明性 Banner
- 表格单元格字段**默认不加粗**

### 2.3 Tab 区规则

- 采用线性下划线式切换
- 日志、操作轨迹、审批记录统一放 Tab，不塞进基本信息卡

## 3. 新增/编辑页骨架

### 3.1 固定结构（从上到下）

```
┌─ 页面标题区 + 页面级主操作 ───────────────────┐
│  页面标题 / 保存 / 提交 / 返回                 │
├─ 基本信息卡片 ────────────────────────────────┤
│  字段分组A → 字段分组B → 字段分组C             │
├─ 表格明细卡片 ────────────────────────────────┤
│  区块标题 / 新增行 / 批量导入                  │
│  明细表格（行内编辑或弹窗编辑）                │
├─ 其他信息卡片 ────────────────────────────────┤
│  备注 / 附件 / 扩展字段                        │
└───────────────────────────────────────────────┘
```

### 3.2 核心规则

- 表单字段统一 **Label 在上、控件在下**
- 默认**一行 4 列**，窄屏递减
- 控件占位文案：Input 用"请输入"，Select 用"请选择"
- 编辑页出现只读场景时，用文本展示而非 disabled 表单
- 每个信息分区独立一张卡片，不要摊成一张大卡

### 3.3 明细行编辑模式

| 场景 | 推荐方式 |
|------|---------|
| 字段少（≤4列） | 行内直接编辑 |
| 字段多（>4列）或含复杂关联 | 弹窗编辑 |
| 需搜索选择外部数据 | 弹窗内搜索选择 |

### 3.4 底部操作栏

- 默认只保留顶部操作，不重复放底部操作栏
- 仅超长表单或顶部操作脱离视口时才启用底部操作栏

## 4. 跨页面通用规则

### 4.1 空值展示

字段无数据时统一展示 **`-`**（连字符），不使用中文破折号或空白。

### 4.2 操作反馈

- 风险操作（删除/取消/关闭）必须 Modal 二次确认
- 确认按钮必须使用语义化文案（"确认删除"而非"确定"）
- 禁止使用 `window.confirm()`

### 4.3 列设置管理范围

- 列设置只管理**业务字段**
- 操作列、勾选列、序号列不进入列设置
- 操作列固定最右侧，勾选列固定最左侧

## 5. 完整模块三步拆分生成法

适用于完整模块（列表+详情+新增编辑）的首次生成：

### Step 1：骨架与列定义

- 搭建页面文件骨架
- 定义表格列（按 PRD 列顺序）
- 定义查询区字段

**用户验证**：列顺序、查询字段是否与 PRD 一致

### Step 2：业务逻辑

- 过滤/排序逻辑
- 批量操作（确认弹窗 + 语义化按钮文案）
- 行内操作
- 页头按钮逻辑

**用户验证**：PRD 按钮矩阵是否全部覆盖

### Step 3：Mock 数据

- 按字段清单枚举生成
- 按 PRD 状态分布生成
- 输出状态覆盖统计表

**用户验证**：看统计表确认覆盖度

## 6. 代码禁止模式

| 禁止写法 | 替代方案 |
|---------|---------|
| `window.confirm(...)` | 使用 Modal 组件 |
| `row.id === "某个具体单号"` | 基于字段值（状态枚举）判断 |
| 确认按钮文案"确定" | 使用"确认删除""确认审核"等语义化文案 |

## 7. 页面交付验收

页面交付前逐条确认：

- [ ] 查询区字段与 PRD 一致

- [ ] 批量操作与行操作完整
- [ ] 详情分区顺序正确
- [ ] Mock 数据覆盖所有状态
- [ ] 无 `window.confirm`
- [ ] 确认按钮文案语义化
- [ ] 构建通过
- [ ] 运行态已检查
