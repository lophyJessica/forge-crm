## 审计方法论（每轮固定框架）

1. 主PRD 行数（≥300 质量下限）
2. 章节完整性（痛点/In-Out/链路/场景/状态机/规则/权限/验收）
3. 状态机闭环（所有状态入口/出口/失败处理）
4. 字段清单 SSOT（下游是否重复定义）
5. 通用规范对照（Tag配色/列表/必填/二次确认/主数据）
6. 上下游一致性（跨系统 SSOT 归属）
7. 用例推演是否存在（方法论第 6 步强关卡）

## 审计分级

- **P0**：阻断性问题——必须清零才部署
- **P1**：重要问题——应修
- **P2**：优化建议——可延后

## 跨模块共性发现（返修优先级最高）

1. **跨系统契约缺失**（商机/合同/业绩都缺 ERP 订单/事件契约）——必须先定 SSOT 边界
2. **字段清单 SSOT 落地不完整**（6 模块全有"Demo 用了清单没定义"的字段）
3. **用例推演覆盖不足**（6 模块全缺异常/逆向/跨系统路径——方法论第 6 步没达标）
4. **金额口径不清**（商机预计/合同签署/ERP 订单——三处关系未收口）
5. **状态模型混淆**（同步处理状态 vs 业务生命周期状态——客户/业绩最明显）

## 返修建议顺序

1. 先定跨系统 SSOT 边界（客户双标识/ERP 契约/金额口径）
2. 补字段清单（6 模块全扩——消除"Demo 用未定义字段"）
3. 补用例推演（异常/逆向/跨系统——达标第 6 步）
4. 收口状态模型（同步状态 vs 业务状态分离）
5. 再进 Demo/前端
