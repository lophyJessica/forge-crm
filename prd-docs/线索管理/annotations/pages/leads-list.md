## 需求描述：【状态页签与线索池视图】

> 来源：`线索_Demo_列表页.md#2-状态 Tab 栏`、`线索主PRD.md#5-状态机`、`线索主PRD.md#6.2 R04`、`线索主PRD.md#6.4 R09/R10`

### 业务定义
- 页面：线索管理/线索列表。默认进入「全部」页签；页签只切换查看范围，不直接改变线索状态。
- 「全部」展示所有线索；「待分配」展示待分配线索（PENDING_ASSIGN）；「我的线索」展示当前销售名下的已分配线索（ASSIGNED）和跟进中线索（FOLLOWING）；「公海」展示可见的待分配线索和保护期结束的已作废/已放弃线索；「已转客户」展示已转客户线索（CONVERTED）；「已作废」展示已作废/已放弃线索（ABANDONED）。
- AI评分只读展示并参与分流：评分达到 80 分及以上为高分线索，自动分配；50-79 分进入待分配池；低于 50 分进入培育池。评分失败时按主 PRD 安全降级为 50 分，进入待分配池（PENDING_ASSIGN）。

### 显示样式
- 共 6 个页签：全部、待分配、我的线索、公海、已转客户、已作废。
- 每个页签右侧显示数量，超过 99 条显示 `99+`；当前页签使用蓝色文字和底部指示线。

### 交互规则
- 切换页签后刷新列表并将页码重置为第 1 页；查询条件按原型说明保留。当前原型同时清空已勾选行，属于页面实现行为。
- 分配后 48 小时未首次跟进的线索自动回收，清除负责人和分配时间，回退到待分配池（PENDING_ASSIGN）；跟进中线索超过 48 小时未追加跟进记录时，也应自动回收到待分配池。
- 线索主动放弃后进入已作废/已放弃状态（ABANDONED），执行 7 天防撞墙保护：保护期内原放弃人和其他销售均不可认领，保护期结束后才向其他销售开放。

### 字段与状态
| 业务状态 | 业务含义 | 终态/视图规则 |
| --- | --- | --- |
| 草稿（DRAFT） | 手动录入后暂存的草稿 | 非终态；仅草稿允许彻底删除 |
| 待分配（PENDING_ASSIGN） | 等待分配的线索，也包括培育池线索 | 非终态；按权限参与待分配和公海视图 |
| 已分配（ASSIGNED） | 已分配负责人但尚未完成首次有效联系 | 非终态；开始计算首次跟进时限 |
| 跟进中（FOLLOWING） | 已完成首次联系并持续跟进 | 非终态；每次新增跟进后重新计算跟进时限 |
| 已转客户（CONVERTED） | 已在 ERP 完成客户建档的线索 | 终态；归档只读，不可再次转客户 |
| 已作废/已放弃（ABANDONED） | 被判定无效或主动放弃并进入公海的线索 | 终态；受 7 天保护期约束 |

### 权限与异常
- 销售只能看到本人负责的线索，以及满足公海保护期规则的可认领线索；销售主管可见团队线索、待分配池和公海；系统管理员全局可见。
- 公海认领、手工分配和自动回收发生并发冲突时，应阻断后到操作并刷新列表；失败时提示线索状态已变更或已被他人认领。

### 研发备注
- 当前原型的「我的线索」还包含当前用户的草稿（DRAFT），与原型说明中的「已分配 + 跟进中」定义不一致，待确认。
- 当前原型允许原负责人在已作废/已放弃（ABANDONED）后立即显示「撤销放弃」，与 7 天防撞墙保护规则不一致，待确认。
- 当前原型的自动回收只在列表数据变化时执行，且只覆盖已分配（ASSIGNED）且无跟进记录的场景；10 分钟定时扫描和跟进中（FOLLOWING）超时回收属于原型待补。

## 需求描述：【线索筛选与查询栏】

> 来源：`线索_Demo_列表页.md#3-查询区`、`线索字段清单.md#一、基础信息字段`、`线索字段清单.md#四、展示规则`

### 业务定义
- 页面：线索管理/线索列表。筛选条件作用于当前状态页签，多个条件同时满足时才保留线索；任一条件变化都应将页码重置为第 1 页。
- 列表默认按创建时间倒序；筛选只改变查看结果，不改变线索状态或客户主数据。

### 显示样式
- 桌面端按 6 列栅格布局，查询区包含关键词、线索来源、所属行业、AI评分区间、负责人和操作区。
- 线索来源选项：官网（ONLINE）、线下活动（ACTIVITY）、展会（EXHIBITION）、转介绍（REFERRAL）、批量导入（IMPORT）、其他（OTHER）。
- 所属行业选项：制造业（MANUFACTURING）、零售（RETAIL）、医疗（HEALTHCARE）、金融（FINANCE）、信息技术（IT）、其他（OTHER）。

### 交互规则
- 关键词按原型说明应支持公司名称、联系人、手机号的多值搜索，值之间允许换行或逗号分隔；当前原型使用单个输入值，并额外匹配线索编号，待确认。
- AI评分按 0-100 分区间筛选，区间含义为大于等于最小分且小于等于最大分；当前原型未明确阻断超出范围或最小分高于最大分的输入，待确认。
- 负责人支持从销售列表中选择；当前原型提供张三、李四两个示例负责人。
- 点击「重置」清空关键词、线索来源、所属行业、AI评分区间、负责人和已勾选项，并回到第 1 页。

### 字段与状态
| 筛选项 | 业务名称/选项 | 核心规则 |
| --- | --- | --- |
| 关键词 | 关键词 | 公司名称、联系人、手机号支持多值搜索；当前原型为单值输入，待确认 |
| 线索来源 | 官网（ONLINE）、线下活动（ACTIVITY）、展会（EXHIBITION）、转介绍（REFERRAL）、批量导入（IMPORT）、其他（OTHER） | 仅使用字段清单定义的 6 个来源选项 |
| 所属行业 | 制造业（MANUFACTURING）、零售（RETAIL）、医疗（HEALTHCARE）、金融（FINANCE）、信息技术（IT）、其他（OTHER） | 仅使用字段清单定义的 6 个行业选项 |
| AI评分 | AI评分 | 0-100 分；80 分及以上、50-79 分、低于 50 分的分级规则与状态页签、表格保持一致 |
| 负责人 | 负责人 | 销售人员列表；当前原型为示例下拉选项 |
| 创建时间 | 创建时间 | 快捷选项：今天、本周、本月；当前页面未呈现，待确认 |

### 权限与异常
- 负责人和公海数据的查看范围受销售、销售主管、系统管理员的数据权限约束，不能通过筛选绕过权限。
- 无符合条件的线索时，应保留当前筛选条件并展示空状态；当前页面文案为「暂无符合条件的线索数据」。

### 研发备注
- 原型说明还定义了「展开/收起」和「搜索」操作区，当前页面只有「重置」且输入后即时筛选，是否补齐待确认。
- 日期筛选、关键词多值能力以及评分边界校验尚未在当前页面实现；本标注仅记录 PRD 要求，不改变现有业务代码。

## 需求描述：【线索表格、批量工具与行操作】

> 来源：`线索_Demo_列表页.md#4-工具条`、`线索_Demo_列表页.md#5-表格`、`线索_Demo_列表页.md#6-二次确认弹窗规格`、`线索字段清单.md#四、展示规则`、`线索主PRD.md#5.3/5.4`、`线索主PRD.md#6.3 R05/R07`、`线索主PRD.md#8-9`

### 业务定义
- 页面：线索管理/线索列表。表格是线索列表的只读业务视图；任何状态变更必须由动作按钮或确认动作触发，不能直接编辑状态。
- 默认每页 20 条，可切换 20、50、100 条；列表按创建时间倒序。点击线索编号进入详情页。
- 工具条按原型说明应支持「新建线索」「批量导入」「导出当前筛选结果」；当前页面已实现前两项，导出待确认。

### 显示样式
- 业务列：线索编号、公司名称、联系人、手机号、邮箱、线索来源、AI评分、线索状态、负责人、最近跟进时间、创建时间；另有勾选列和操作列。
- 状态标签颜色：草稿（DRAFT）灰色、待分配（PENDING_ASSIGN）蓝色、已分配（ASSIGNED）橙色、跟进中（FOLLOWING）绿色、已转客户（CONVERTED）绿色、已作废/已放弃（ABANDONED）红色。
- AI评分标签颜色：80 分及以上绿色、50-79 分黄色、低于 50 分红色。
- 无符合条件的线索时展示「暂无符合条件的线索数据」；字段缺失值以「—」展示。

### 交互规则
| 线索状态 | 列表行内动作 | 动作结果/边界 |
| --- | --- | --- |
| 草稿（DRAFT） | 查看 / 编辑 / 删除 | 删除必须二次确认，且删除后不可恢复；只允许删除草稿 |
| 待分配（PENDING_ASSIGN） | 查看 / 认领 | 认领后写入负责人和分配时间，变为已分配（ASSIGNED）；发生冲突时阻断操作 |
| 已分配（ASSIGNED） | 查看 / 跟进 / 放弃 | 跟进成功后变为跟进中（FOLLOWING）；放弃必须填写原因并进入公海 |
| 跟进中（FOLLOWING） | 查看 / 跟进 / 转客户 / 放弃 | 只有 ERP 建档成功后才变为已转客户（CONVERTED）；放弃必须填写原因 |
| 已转客户（CONVERTED） | 查看 | 终态只读，不可编辑或再次转客户 |
| 已作废/已放弃（ABANDONED） | 查看；保护期后按权限认领 | 受 7 天防撞墙保护；当前原型对原负责人显示「撤销放弃」，待确认 |

- 勾选行后显示批量操作区；「批量作废」需二次确认，确认后选中线索变为已作废/已放弃（ABANDONED），并清空选择。
- 「放弃」弹窗必须要求填写至少 15 字的放弃原因；不满足字数时阻断提交。当前原型只校验非空，长度校验待补。
- 「转客户」在详情页发起，列表只负责进入对应详情场景；ERP 建档失败时应保持跟进中（FOLLOWING），不写入转化时间或客户快照，并提示同步失败原因。

### 字段与状态
| 列/字段 | 列表规则 |
| --- | --- |
| 线索编号 | 系统生成的唯一标识，点击进入详情；当前展示为链接色 |
| 公司名称 | 文本，最多 100 字符；当前原型显示为加粗文本 |
| 联系人 | 选填文本，最多 50 字符；缺失显示「—」 |
| 手机号 | 11 位数字、唯一校验；当前以等宽字体显示 |
| 邮箱 | 邮箱格式、唯一校验；当前以等宽字体显示 |
| AI评分 | 系统生成的 0-100 整数；按分数区间使用绿、黄、红标签 |
| 线索状态 | 系统生成，由状态流转驱动；不在表格中直接修改 |
| 负责人 | 分配时写入，自动回收时清空；缺失显示「—」 |
| 最近跟进时间 | 系统生成，作为跟进中超时回收依据；缺失显示「—」 |
| 创建时间 | 系统生成；列表默认按此倒序 |

### 权限与异常
- 销售只能跟进本人负责的线索；导入、手动分配、强行废弃等能力按销售、销售主管、系统管理员的权限矩阵控制。
- 认领、分配和自动回收发生并发冲突时，后到操作应提示状态已变更或已被他人认领，并刷新列表；关键操作还应防止重复提交。
- 客户主数据不做常规删除；本列表的「删除」仅对应 PRD 明确允许的草稿彻底删除，其他关闭动作使用「作废/放弃」状态流转。

### 研发备注
- 当前原型已实现状态标签、AI评分标签、分页、勾选、草稿删除、放弃弹窗、批量作废确认和批量导入示例流程。
- 当前原型未实现列宽拖拽、左右固定列、导出、创建时间筛选、批量分配；这些是原型说明中的页面缺口，待确认。
- 当前原型的自动回收只覆盖已分配（ASSIGNED）且无跟进记录，并未覆盖主 PRD 要求的跟进中（FOLLOWING）最近跟进超时，属于原型待补。
- 当前原型在放弃时只写入已作废/已放弃（ABANDONED）、原因和时间，未按主 PRD 清空负责人和分配时间；该状态流转细节待确认。
