## 返修用例1：三类事件重复投递去重

| 项目 | 数据/动作 |
|------|-----------|
| 销售ID/目标月份/目标值 | `S001` / `2026-07` / 线索 10、商机 5、赢单 50,000.00 CNY |
| 事件ID/事件时间/金额 | `LEAD-CVT-001` / `2026-07-10 09:00` / 0；`OPP-CREATE-001` / `2026-07-11 10:00` / 0；`CRM-WON-001` / `2026-07-20 15:00` / 30,000.00 CNY；ERP `ORD-CONF-001` / `2026-07-20 16:00` / 30,000.00 CNY；以上事件各重复投递 1 次 |
| 前后状态 | `ACTIVE + NOT_STARTED` → `ACTIVE + NOT_STARTED` |
| 快照结果 | 线索只计 1、商机只计 1、CRM WON 只计 30,000.00、ERP确认订单只计 30,000.00；重复记录为 `DUPLICATE`，无结算快照 |
| 结论 | 三类事件均按来源事件ID/订单事实键幂等，不重复累计 |

## 返修用例2：结算失败重试保留原截止快照

| 项目 | 数据/动作 |
|------|-----------|
| 销售ID/目标月份/目标值 | `S002` / `2026-06` / 线索 10、商机 5、赢单 100,000.00 CNY |
| 事件ID/事件时间/金额 | `LEAD-CVT-002` / `2026-06-30 20:00` / 0；`OPP-CREATE-002` / `2026-06-30 20:05` / 0；ERP `ORD-CONF-002` / `2026-06-30 21:00` / 100,000.00 CNY |
| 前后状态 | `ACTIVE + NOT_STARTED` → `ACTIVE + PROCESSING` → `ACTIVE + FAILED` → 点击动作按钮 → `ACTIVE + RETRYING` → `ACHIEVED + SUCCESS` |
| 快照结果 | 失败原因、任务编号、截止时间 `2026-07-01 00:00:00+08:00`、重试次数保留；重试仍读取原截止时间，成功只生成版本 `V1` 一份快照 |
| 结论 | 失败不伪造 `UNACHIEVED`；重试沿用原截止时间和幂等键 |

## 返修用例3：结算并发只生成一份快照

| 项目 | 数据/动作 |
|------|-----------|
| 销售ID/目标月份/目标值 | `S003` / `2026-05` / 线索 5、商机 3、赢单 80,000.00 CNY |
| 事件ID/事件时间/金额 | `LEAD-CVT-003` / `2026-05-31 23:00` / 0；`OPP-CREATE-003` / `2026-05-31 23:10` / 0；ERP `ORD-CONF-003` / `2026-05-31 23:20` / 80,000.00 CNY |
| 前后状态 | 两个结算执行器同时提交：`ACTIVE + NOT_STARTED` → 一个 `ACTIVE + PROCESSING`，另一个命中锁；最终 `ACHIEVED + SUCCESS` |
| 快照结果 | 只有一个结算任务成功、一个结算版本 `V1`、一个锁定时间和一份快照；第二次返回首次成功结果 |
| 结论 | 目标级结算锁+目标编号/月份幂等键阻止重复快照 |

## 返修用例4：结算锁与编辑并发

| 项目 | 数据/动作 |
|------|-----------|

| 事件ID/事件时间/金额 | `LEAD-CVT-004` / `2026-08-31 23:59:58` / 0；ERP `ORD-CONF-004` / `2026-08-31 23:59:59` / 50,000.00 CNY |
| 前后状态 | 编辑页提交调整与结算同时发生：先进入 `ACTIVE + PROCESSING`；编辑动作被阻断；结算成功后为 `ACHIEVED + SUCCESS` |
| 快照结果 | 锁定时间早于编辑保存提交时间；目标值、进度和快照不被表单覆盖；编辑提示结算锁冲突 |
| 结论 | 结算锁优先，编辑并发不能突破锁或移动目标线 |

| 事件ID/事件时间/金额 | 无业务事件（事件时间/金额均无）；尝试创建请求 `REQ-012-A`、`REQ-012-B` |
| 前后状态 | 未映射请求无状态/不落库；`S001 + 2026-08` 已有 `ACTIVE + NOT_STARTED`，重复请求后状态不变 |
| 快照结果 | 未映射销售阻断并提示完成映射；已映射销售重复请求返回已有目标；不生成第二条目标、不生成结算快照 |
| 结论 | 销售ID映射是创建前置；同销售同月唯一约束防止重复目标 |
