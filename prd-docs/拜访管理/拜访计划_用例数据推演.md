# 拜访计划_用例数据推演

> **版本**：V2.0 | 2026-08-13
> **测试口径**：服务端时间为准；所有动作均通过按钮触发；失败不覆盖原状态/事实并写审计日志。

## 1. 测试数据

| 数据 | 示例 |
|---|---|
| 销售 | `SALES001`，角色 `OWNER`，负责人；主管 `SUP001`；管理员 `ADM001` |
| 线索 | `LEAD001`，状态 `OPEN`，名称快照“华东制造线索” |
| 商机 | `OPP001`，状态 `OPEN`，客户 `CUST001` |
| 客户 | `CUST001`，ERP 生命周期 `ACTIVE`、同步 `AVAILABLE`；备选同步状态 `PENDING_RECEIVE`、`VALIDATING`、`SYNC_FAILED`，生命周期 `DISABLED` |
| 正常拜访 | `VS20260813-0001`，`ONSITE`，`2026-08-13 10:00—11:00`，关联 `OPP001` |
| 电话拜访 | `VS20260813-0002`，`PHONE`，关联 `CUST001` |
| 幂等 | `visit:VS20260813-0001:complete:v1`；签到/改期/跟进分别使用同一业务动作的唯一键 |

## 2. 正常路径

### 用例 01：正常上门拜访闭环

| 项目 | 推演 |
|---|---|
| 输入数据 | `VS...0001`，`PLANNED + NOT_STARTED`，客户 ACTIVE，负责人 SALES001。 |
| 当前状态 | `primaryStatus=PLANNED`，`executionResult=NOT_STARTED`，`checkInAt=NULL`。 |
| 动作 | 创建 → `CHECK_IN`（允许浏览器定位）→ 填反馈 → `COMPLETE`。 |
| 前置校验 | 权限、版本、客户 ACTIVE、关联商机 OPEN；反馈必填；服务端时间在动作窗口内。 |
| 时间/定位结果 | `checkInAt` 使用服务端 `Asia/Shanghai` 时间；`locationSource=BROWSER`，授权 GRANTED，保存经纬度/精度。 |
| 状态变化 | `PLANNED→CHECKED_IN→COMPLETED`；`executionException=NONE`。 |
| 失败提示 | 任一校验失败 Toast 具体原因；不完成；网络失败可重试。 |
| 结论 | 3 条操作日志落库；反馈字段落库；有下一步时生成唯一 `followUpRecordId`；商机阶段不自动改变。 |

## 3. 状态和异常路径

### 用例 02：计划时间过但未签到

| 项目 | 推演 |
|---|---|
| 输入数据 | `VS...0001`，计划结束 `11:00`，服务端当前 `11:05`，无签到。 |
| 当前状态 | `PLANNED + NOT_STARTED`，`overdueFlag=false` 初始。 |
| 动作 | 刷新列表后展示“已超时待处理”，点击“标记未到访”。 |
| 前置校验 | 服务端 `now>plannedEndAt`、`checkInAt=NULL`、角色有权限、`missedReason` 必填。 |
| 时间/定位结果 | 不请求定位；`missedAt` 使用服务端时间。 |
| 状态变化 | 计算提示不改状态；确认后 `executionResult=NOT_STARTED→MISSED`。 |
| 失败提示 | 未过截止时间或已被他人签到：“当前条件不满足标记未到访，请刷新后重试”。 |
| 结论 | `MISSED`、原因、操作者、时间和审计日志落库；不能直接点完成。 |

### 用例 03：未开始计划改期

| 项目 | 推演 |
|---|---|
| 输入数据 | `VS...0001`，未签到；新时间为次日 10:00。 |
| 当前状态 | `PLANNED + NOT_STARTED`。 |
| 动作 | 点击“改期”，填 `rescheduleReason=CUSTOMER_RESCHEDULE`，确认。 |
| 前置校验 | 新时间合法；客户/商机提交前校验；无并发版本冲突。 |
| 时间/定位结果 | 不签到、不请求定位；原计划时间不变。 |
| 状态变化 | 原单 `executionResult→RESCHEDULED`；新单 `PLANNED + NOT_STARTED`，双向 `rescheduledFrom/ToVisitId`。 |
| 失败提示 | 新时间非法/接口失败：“改期失败，请修正时间后重试”；原单保持不变。 |
| 结论 | 原单和新单各自落库，关联链路可追溯；重复点击不产生重复新单。 |

### 用例 06：PC Web 无法签到/拒绝定位

| 项目 | 推演 |
|---|---|
| 输入数据 | `ONSITE` 拜访，浏览器定位权限 DENIED 或不支持；客户 ACTIVE。 |
| 当前状态 | `PLANNED + NOT_STARTED`。 |
| 动作 | 点击签到；定位失败弹窗确认“无定位签到”。 |
| 前置校验 | 状态、权限、客户状态和服务端时间均通过；用户完成无定位确认。 |
| 时间/定位结果 | `locationSource=NONE`，`authorizationResult=DENIED/UNSUPPORTED`，坐标 NULL；`checkInAt` 为服务端时间。 |

| 失败提示 | 用户未确认：“签到未完成，可授权后重试”；网络失败：“签到失败，请重试”。 |
| 结论 | 不因 GPS 阻断；定位授权结果和失败原因落库；页面不伪装真实 GPS。 |

## 4. 汇总结论

| 检查项 | 预期落库/变化 |
|---|---|
| 状态动作 | 每例明确当前状态、按钮、权限、前置校验和状态变化；状态字段没有直接编辑入口。 |
| 时间定位 | 所有签到时间服务端生成；电话/视频不请求定位；拒绝定位不阻断；Mock 明确标识。 |
| 关联与停用 | 关联稳定 ID 和快照保留；客户停用禁新签到但允许已签到完成；商机输单保留历史。 |
| 异常与重试 | 网络/Mock/跟进失败有具体 Toast、原状态保留和幂等重试；冲突需刷新。 |
| 审计 | 取消、改期、签到、代签、完成、补反馈、主管修正、补录均写操作日志。 |
