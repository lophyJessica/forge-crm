# 拜访计划 Demo：详情页

> **版本**：V2.0 | 2026-08-13  
> **页面路由**：`/crm/visits/:visitId`  
> **页面目标**：展示拜访全链路事实、可用动作、关联快照、反馈版本和操作审计。

## 2. 顶部摘要与动作

| 控件/区域 | 规则 |
|---|---|
| 面包屑 | 返回列表；不丢失列表筛选条件。 |
| 主状态 Tag | `PLANNED` 蓝、`CHECKED_IN` 橙、`COMPLETED` 绿、`CANCELLED` 红；执行结果另显示 `MISSED` 紫、`RESCHEDULED` 灰。 |
| `签到` Button | 仅 PLANNED 且满足前置校验显示；上门可请求浏览器定位，电话/视频直接签到；二次确认。 |
| `完成拜访` Button | 仅 CHECKED_IN 显示；反馈必填；二次确认；成功 Toast；跟进失败提供重试。 |
| `取消` More Action | 未签到由负责人/主管/管理员操作；已签到仅主管/管理员显示“已签到后取消”；二次确认+原因。 |
| `改期/重新计划` More Action | PLANNED NOT_STARTED/MISSED 显示；生成新单，不覆盖原时间；二次确认+原因。 |
| `标记未到访` More Action | 仅过截止时间且无签到的 PLANNED NOT_STARTED；原因必填；动作按钮触发，不自动落库。 |
| `代签` More Action | 仅主管/管理员；显示实际执行人、代签原因和证据说明；不伪造本人签到。 |
| `编辑计划` More Action | 仅未签到未终态记录；不编辑状态；关联更换为独立受控动作。 |
| `补充反馈` More Action | COMPLETED 仅主管/管理员；追加反馈版本，原始事实只读。 |
| `退回反馈` More Action | 主管/管理员；填写 `returnReason`，状态仍 COMPLETED，反馈审核状态变 RETURNED。 |
| `主管修正` More Action | 主管/管理员；只允许修正异常分类、反馈等非原始事实；原因必填。 |
| `重试生成跟进` | 仅 `FOLLOW_UP_PENDING` 显示；使用原幂等键，成功后回写 `followUpRecordId`。 |

## 3. 信息分区

### 3.1 计划信息

展示 `visitId`、`title`、`visitMethod`、`plannedStartAt`、`plannedEndAt`、`assigneeId`、`address`、`source`。时间统一 `Asia/Shanghai`；字段空值显示 `—`。

### 3.2 执行信息

展示 `primaryStatus`、`executionResult`、`checkInAt`、`completedAt`、`actualExecutorId`、`checkInMethod`、`locationSource`、`locationReliability`、`authorizationResult`、`accuracyMeters` 和定位失败原因。

- 未签到 `checkInAt=—`；已签到后取消保留实际签到时间。
- `locationSource=MOCK` 必须显示醒目标识“Mock 定位”，不显示“GPS 已验证”。
- 电话/视频展示“未请求定位”；拒绝授权展示“无定位签到”，不阻断已成功的签到。
- 定位数据只展示一次签到证据，不提供轨迹回放或地图导航。

### 3.3 反馈信息

展示并按条件编辑 `visitResult`、`customerIntent`、`feedbackContent`、`nextAction`、`nextFollowUpAt`、`nextActionOwner`、`followUpRecordId` 和 `feedbackReviewStatus`。

- CHECKED_IN：负责人可保存草稿、提交完成；完成前校验必填。
- COMPLETED：普通销售只读；主管/管理员可补充反馈，形成递增 `feedbackVersion`。
- 反馈退回：显示 `returnReason`；负责人补充后重新提交，不改完成事实。
- 无下一步：明确展示“未创建跟进：本次无下一步行动”，而不是空白。
- 跟进创建失败：显示“拜访已完成，跟进待生成”和“重试生成跟进”按钮。

### 3.4 关联对象

展示 `relatedObjectType`、`relatedObjectId`、`relatedObjectNameSnapshot`、`relatedObjectStatusSnapshot`。关联商机时同时展示 `inheritedCustomerId` 和客户快照，但明确“主关联对象=商机”。

- 线索转客户：展示 `LEAD001 → convertedToCustomerId` 映射，不覆盖原关联。
- ERP 客户停用：展示当前状态与当时快照；已签到允许完成的规则在操作提示中明确。
- 商机输单：历史拜访仍可查看；未执行计划隐藏签到并提示通过取消动作收口。

### 3.5 改期链路

以时间线或链路卡展示原单、新单和 `rescheduledFromVisitId/rescheduledToVisitId`；原单计划时间只读、改期原因可查。重复改期沿链路追加，不把原单改成新时间。

### 3.6 异常与审计时间线

按服务端时间倒序展示：创建、签到、代签、定位结果、保存反馈、完成、取消、改期、标记未到访、转交、客户状态校验、补反馈、主管修正、跟进重试。每条至少包含操作人、角色、动作、前后状态、原因、`operationId`、`idempotencyKey` 和结果。

## 4. 状态详情示例

| 组合 | 详情页表现 | 可用动作 |
|---|---|---|
| `PLANNED + NOT_STARTED` | 蓝色已计划；未签到时间显示 `—` | 编辑、签到、取消、改期；过期后增加标记未到访。 |
| `PLANNED + MISSED` | 蓝色已计划 + 紫色未到访；原因可查 | 重新计划、取消、审计。 |
| `PLANNED + RESCHEDULED` | 灰色已改期；显示新单链接 | 查看链路、审计。 |
| `CHECKED_IN` | 橙色已签到；签到来源、时间和定位证据可查 | 保存反馈、完成；主管可已签到后取消。 |
| `COMPLETED` | 绿色已完成；完成时间和跟进 ID 可查 | 销售只读；主管/管理员补充、退回、修正。 |
| `CANCELLED` 未签到 | 红色已取消；签到时间 `—` | 只读、审计。 |
| `CANCELLED` 已签到 | 红色已签到后取消；保留签到时间/定位/草稿 | 只读、审计。 |

## 5. 弹窗、Toast 与失败态

| 动作 | 二次确认内容 | 成功 Toast | 失败和重试 |
|---|---|---|---|
| 签到 | 当前对象、拜访方式、是否无定位签到 | “签到成功” | 状态/ERP/权限失败不改状态；网络失败可重试。 |
| 完成 | 反馈摘要、是否生成下一步跟进 | “拜访已完成” | 反馈校验阻断；跟进失败保留完成并可重试。 |
| 取消 | 取消原因、是否已签到、不可逆提示 | “拜访已取消” | 已签到普通角色阻断；冲突需刷新。 |
| 改期 | 原时间、新时间、原单保留提示 | “已生成新拜访” | 新单失败原单不变；沿用幂等键重试。 |
| 标记未到访 | 截止时间、原因、不可自动恢复提示 | “已标记未到访” | 未过期/已有签到阻断；刷新后重试。 |
| 代签/主管修正 | 操作人、原因、原始事实保留提示 | “已完成主管操作” | 权限/版本失败；原事实不覆盖。 |

## 6. 详情页验收

| 编号 | Given | When | Then |
|---|---|---|---|
| D01 | `PLANNED` 且未签到 | 打开详情 | 签到时间为 `—`，显示签到/取消/改期按钮，不显示完成按钮。 |
| D02 | 已签到后取消 | 打开详情 | 签到时间和定位保留，顶部显示已签到后取消，取消原因和时间线可查。 |
| D03 | `COMPLETED` 普通销售 | 打开详情 | 计划、执行、反馈事实只读；不出现删除或取消按钮。 |
| D04 | `COMPLETED` 主管 | 点击补充反馈 | 只能追加新版本；原 `checkInAt`/`completedAt`/定位不可编辑；写审计。 |
| D05 | 定位 Mock | 打开执行信息 | 明确显示 `Mock 定位` 和 `locationReliability=MOCK`。 |
| D06 | `FOLLOW_UP_PENDING` | 点击重试 | 使用相同幂等键；成功显示 `followUpRecordId`，失败保留重试入口。 |
| D07 | 改期原单 | 打开详情 | 原计划时间不变，展示新单链接和改期原因。 |
